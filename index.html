Tokens CSS & conflits de thèmes — comparaison technique à terminer

Seule la colonne design system est vérifiée dans le code local. Les valeurs applicatives n’ont pas pu être lues : aucune équivalence hex/HSL ou mapping sémantique ne peut encore être approuvé.

  • Couleurs : --deep: #1f3f28, --accent: #a3d65c, --ink: #1d252c, --text: #485563, --sand: #f6f7f5, --line: #e5e7eb, --focus: #537d36. Bouton principal : #192e28. Relever en face les tokens sémantiques, valeurs light/dark et classes codées en dur.
  • Typographie : DM Sans corps, Manrope titres. Space Grotesk / Inter côté application n’est qu’une référence antérieure ; vérifier imports, poids, métriques et héritage avant adaptation.
  • Rythme : grille 4 px, marges clamp(20px, 4.5vw, 64px), rayon de base 12 px, assistant 24 px, icônes 24 px / 1,5 px. Comparer les breakpoints réels, rayons et tailles des primitives plutôt que remplacer globalement.
  • Risque confirmé dans ce laboratoire : :root, sélecteurs de balises (body, nav, input, dialog) et noms génériques (.field, .primary, .chip) ne sont pas isolés pour une application multi-thème. Ne jamais importer cette feuille entière dans Matt Mez Admin.
  • Conflits applicatifs possibles, non constatés : providers de thème, classes Tailwind/primitives, variables de même nom et portails rendus hors de la racine Landing. Relever chaque racine public/admin/client et la cible des portails avant de proposer un namespace.
  • Éditeur : appliquer les tokens Landing à son aperçu, pas aux outils privés. Conserver sélection, poignées, toolbar, validation, états dirty/save/publish et focus ; vérifier la spécificité et l’héritage avec les mêmes données publiques.
Reprendre l’audit — commandes en lecture seule et fichiers nécessaires

À exécuter ultérieurement sur une connexion GitHub autorisée au dépôt exact. Ces commandes sont fournies, pas exécutées ici. Aucun clone, installation, mutation ou lecture de données Base44 n’est nécessaire.

Confirmer l’accès et la révision sans afficher de jeton :

gh api repos/mattmezstitchlab/matt-mez-admin --jq '{full_name,default_branch}'

gh api 'repos/mattmezstitchlab/matt-mez-admin/commits?per_page=1' --jq '.[0].sha'

Dans une copie autorisée déjà disponible, remplacer le chemin absolu ci-dessous ; les résultats restent locaux et doivent être relus avant partage :

APP=/chemin/absolu/vers/matt-mez-admin

git -C "$APP" rev-parse HEAD

git -C "$APP" ls-files 'src/*' '*tailwind*' '*postcss*' 'package.json' '*lock*' '*config*'

rg -n -U -g '*.{jsx,tsx,js,ts}' 'lucide-react|@lucide|createLucideIcon' "$APP/src"

rg --files "$APP/src" | rg '(Landing|Hero|Assistant|Gallery|Galerie|Instant|Form|Document|Devis|Quote|Client|Layout|Theme|/ui/|[.]css$)'

rg -n -g '*.{css,jsx,tsx,js,ts}' -- ':root|--[a-zA-Z][a-zA-Z0-9-]*|atelier-clair|dark:|data-theme|ThemeProvider|createPortal|Portal' "$APP/src"

rg -n -g '*.{jsx,tsx,js,ts}' 'className|style=|defaultProps|PropTypes|useState|onChange|onSubmit|schema|safeParse|zod|yup|base44|draft|publish|preview' "$APP/src"

Les recherches sont des points d’entrée, pas un inventaire fini : suivre les imports/exports, usages JSX, aliases et registres dynamiques pour exclure les icônes non utilisées et identifier les vraies props. Inspecter aussi les dépendances, la configuration CSS et les tests existants.

Fichiers nécessaires : Landing, Hero, assistants desktop/mobile, INSTANTS, GallerySection, LandingEditor et son renderer d’aperçu, GalerieEditor, formulaires et schémas de validation, primitives, documents/devis, layouts/routage/providers et styles public/admin/client. Partager uniquement le code autorisé utile, chemins et numéros de ligne ; exclure secrets, .env, exports clients et données de production.

Pour chaque ligne de matrice : relever la révision Git, le chemin/symbole/ligne, classes/tokens actuels, props/types/defaults/nulls, callbacks et tests associés. Marquer « inspecté dans le code » séparément de « vérifié visuellement ». L’accès au code ne valide ni un rendu mobile ni une page authentifiée.

Critère de sortie : aucune migration autorisée tant que l’inventaire réel Lucide, les contrats public/éditeur, les tokens par thème et les tests métier associés ne sont pas documentés. La matrice actuelle est un dossier de reprise exploitable, pas une certification de compatibilité.

  1. Compléter les preuves. Suivre les commandes de reprise ci-dessus, relever la révision et les références fichier/ligne, puis les composants et usages Lucide réels. Garder distincts audit du code et validation visuelle à 375, 390, 768, 1024 et 1440 px ; lister les routes privées non vérifiées.
  2. Valider les contrats de données. Relever les props publiques / éditeur, champs média et fallbacks. Adapter ce prototype aux données existantes, jamais l’inverse.
  3. Isoler les styles. Tokens sous une racine Landing dédiée ; ne pas copier :root, styles de balises ou variables globales de ce laboratoire dans Matt Mez Admin.
  4. Partager le rendu. Un composant public réutilisé par l’aperçu brouillon, avec commandes d’édition séparées. Comparer les mêmes données desktop / mobile avant intégration.
  5. Porter par famille après accord. D’abord boutons / champs / cartes ; puis navigation et médias ; assistant en dernier, sans toucher aux moteurs, demandes, devis, documents ou permissions. Espace client et administration restent spécifiques.
  6. Recette et retour arrière. Comparaisons visuelles, clavier, contrastes, erreurs et tests métier existants. Faire valider chaque étape et préserver la possibilité de revenir aux styles précédents. Aucune publication automatique.

Vérifiés : menu / Échap, onglets / flèches / Home / End, validation et correction des formulaires, suggestions et erreur du chat sans perte de texte, hauteur stable et scroll interne, carrousel, modale, états de chargement, sauvegarde locale réussie / échouée, modifications pendant sauvegarde, reset et absence de persistance au rechargement. Texte HTML rendu sans interprétation.

Focus vert vérifié sur texte, select, date, textarea et saisie du chat, y compris mode couleurs forcées. Animations et transitions coupées avec prefers-reduced-motion. Contrastes calculés : texte / blanc 7,62:1 ; bouton 14,36:1 ; sélection 8,43:1 ; erreur 7,19:1 ; bordure de focus / blanc 4,82:1.

Lecteur local testé avec un WebM de démonstration, lecture volontaire et pause ; fichier non vidéo rejeté. Les polices Google et photographies Unsplash ne chargent pas dans cet environnement : leur rendu définitif et les contrastes dépendant des photographies restent à vérifier. Safari, iOS, Android, moteurs métier et écrans de production ne sont pas validés par ces tests.
